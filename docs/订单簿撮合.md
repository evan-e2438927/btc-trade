## 1. 什么是订单簿

**订单簿**（Order Book）是交易所维护的一张实时清单，记录了所有**尚未成交的挂单**——包括买家愿意出的价格、卖家要求的价格，以及对应的数量。

### 通俗类比

> 把订单簿想象成一个**农贸市场的公告板**：
> - 左边写着买家出价："我出 64900，要买 0.5 个 BTC"
> - 右边写着卖家要价："我要 65000，卖 0.3 个 BTC"
>
> **撮合引擎**就是那个在中间撮合双方的"市场管理员"——当买家出价 ≥ 卖家要价时，立刻撮合成交。

---

## 2. 订单簿的结构

订单簿由两个方向的挂单组成：

| 方向 | 名称 | 说明 |
|------|------|------|
| 买方挂单 | **Bid（买盘）** | 买家愿意支付的最高价，从高到低排列 |
| 卖方挂单 | **Ask（卖盘）** | 卖家愿意接受的最低价，从低到高排列 |

### 可视化示意

```
         卖盘（Ask / 卖方）
  ┌──────────────────────────────┐
  │  价格（USDT）   数量（BTC）   │
  │  65200         1.20          │  ← 卖价最高（离市价最远）
  │  65150         0.85          │
  │  65100         0.50          │
  │  65050         0.30          │
  │  65000         0.20          │  ← 最优卖价（Ask Price）
  ├──────────────────────────────┤
  │          当前价差（Spread）   │  ← 买一价与卖一价之间的空隙
  ├──────────────────────────────┤
  │  64990         0.40          │  ← 最优买价（Bid Price）
  │  64950         0.60          │
  │  64900         1.10          │
  │  64850         0.75          │
  │  64800         2.00          │  ← 买价最低（离市价最远）
  └──────────────────────────────┘
         买盘（Bid / 买方）
```

- **最优卖价（Best Ask）**：卖方挂单中最低的价格，买方市价单会优先在这里成交
- **最优买价（Best Bid）**：买方挂单中最高的价格，卖方市价单会优先在这里成交

## 3. 撮合引擎的工作原理

**撮合引擎**（Matching Engine）是交易所的核心模块，负责将买卖双方配对成交。

### 撮合条件

```
当 买方出价（Bid） ≥ 卖方要价（Ask） 时 → 立即撮合成交
```

### 撮合流程

```
新买单进来（价格 65000）：
        ↓
检查卖盘最优价（Ask）= 65000
        ↓
买价(65000) ≥ 卖价(65000) → ✅ 条件满足
        ↓
以成交价 65000 撮合双方
        ↓
从订单簿中移除已成交的挂单
        ↓
记录成交数据到 trades 表
```

---

## 4. 撮合的优先级规则

当有多个挂单都满足撮合条件时，遵循以下优先级：

### 规则一：价格优先

对买方来说，出价越高 → 优先成交；  
对卖方来说，要价越低 → 优先成交。

```
卖盘挂单（按价格从低到高）：
  65000 × 0.2 BTC  ← 最优，优先被买方撮合
  65050 × 0.3 BTC
  65100 × 0.5 BTC
```

### 规则二：时间优先（FIFO）

相同价格的挂单中，**先挂单的先成交**（First In, First Out）。

```
同为 65000 的卖单：
  09:01:00  张三挂 0.1 BTC  ← 先挂，先成交
  09:01:05  李四挂 0.2 BTC
  09:01:10  王五挂 0.3 BTC
```

> 完整规则：**价格优先，时间次之**

## 5. 市价单的撮合过程

市价单（Market Order）进入后，立即从**最优价**开始，依次"吃掉"对方订单簿，直到全部成交。

### 示例：市价买入 0.8 BTC

```
当前卖盘：
  65000  ×  0.2 BTC
  65050  ×  0.3 BTC
  65100  ×  0.5 BTC

市价买单 0.8 BTC 进入：

第一步：以 65000 成交 0.2 BTC（卖盘第一档全部吃掉）
第二步：以 65050 成交 0.3 BTC（卖盘第二档全部吃掉）
第三步：以 65100 成交剩余 0.3 BTC（卖盘第三档部分吃掉）

成交明细：
  0.2 BTC × 65000 = 13000.00 USDT
  0.3 BTC × 65050 = 19515.00 USDT
  0.3 BTC × 65100 =  9530.00 USDT  （第三档剩余 0.2 BTC）
  ──────────────────────────────────
  合计：0.8 BTC，共花费 42045.00 USDT

平均成交价 = 42045 / 0.8 = 52556.25 USDT
（实际上应为 65056.25，此处仅作示意）

与最优价的滑点 = 65056.25 - 65000 = 56.25 USDT/BTC
```

**结论**：买的量越大，"吃"的价格层级越多，平均价格越高，滑点越大。

## 6. 限价单的撮合过程

限价单（Limit Order）以**指定价格**挂入订单簿，只有市场价格到达时才成交。

### 示例：限价买单 @ 64900

```
当前最优卖价（Best Ask）= 65000

买家挂限价单 64900：
  ├── 64900 < 65000（卖价）→ 条件不满足，不能立即成交
  └── 将此买单加入买盘：64900 × N BTC，等待

日后价格下跌，出现卖家挂单 64900 或更低：
  └── 买价(64900) ≥ 卖价(64900) → 撮合成交！
```

### 限价单的两种情况

| 情况 | 说明 |
|------|------|
| 挂单价优于当前市场价 | 立即作为"主动方"与对方最优挂单成交 |
| 挂单价劣于当前市场价 | 进入订单簿等待，直到对方价格到达 |

**举例（立即成交）**：

```
当前卖盘最优价 = 65000
你挂限价买单 @ 65100（高于卖价）
  → 65100 ≥ 65000 → 立即以 65000 成交（以卖方的价格为准，对你更有利）
```

## 7. 部分成交

当你的订单数量大于对方最优挂单数量时，订单会**部分成交**，剩余部分继续挂单等待。

```
你的限价买单：1.0 BTC @ 65000

当前卖盘 @ 65000 只有：0.3 BTC

撮合结果：
  ├── 0.3 BTC 立即成交
  └── 0.7 BTC 继续在买盘中等待

订单状态：partial（部分成交）→ 等待更多卖单
```

> 📌 本系统简化实现：采用**全量一次成交**，不处理部分成交逻辑。

## 8. 买卖价差（Spread）

**价差**（Spread）= 最优卖价（Best Ask）- 最优买价（Best Bid）

```
Best Ask = 65000
Best Bid = 64990
Spread   = 10 USDT
```

### 价差的意义

| 价差大小 | 含义 | 影响 |
|---------|------|------|
| 价差小（1~5 USDT） | 流动性好，买卖双方供给充足 | 成交容易，滑点小 |
| 价差大（50+ USDT） | 流动性差，市场不活跃 | 成交难，滑点大 |

> BTC/USDT 主流交易对的价差通常在 1~10 USDT，小币可能高达数百美元。

## 9. 订单簿深度与流动性

**深度**（Depth）是指订单簿在某个价格范围内的挂单总量。深度越大，流动性越好。

```
浅深度订单簿（流动性差）：
  65100  ×  0.01 BTC
  65050  ×  0.02 BTC
  65000  ×  0.01 BTC   ← 0.04 BTC 就能把这三档全部吃完

深深度订单簿（流动性好）：
  65100  ×  10.00 BTC
  65050  ×  25.00 BTC
  65000  ×  50.00 BTC   ← 需要 85 BTC 才能吃完这三档
```

**对滑点的影响**：

$$
\text{深度越大} \Rightarrow \text{大单冲击越小} \Rightarrow \text{滑点越小}
$$

## 10. 本系统与真实订单簿的对比

本系统为教学/模拟系统，**没有实现真正的双边订单簿撮合**，而是采用简化方案：

| 特性 | 真实交易所 | 本系统 |
|------|-----------|--------|
| 订单簿结构 | 完整的买盘/卖盘挂单列表 | 无（用 `priceStore` 单一价格代替） |
| 市价单成交 | 依次吃对方挂单，逐档成交 | 直接以当前价格全量成交 |
| 限价单撮合 | 进入订单簿排队等待反向挂单 | 引擎轮询：当前价 ≤ 买单价 / ≥ 卖单价时触发 |
| 部分成交 | 支持（挂单数量超出时） | 不支持（全量一次成交） |
| 滑点 | 真实存在（大单多档成交） | 零滑点（单一价格成交） |
| 价差 | 实时变化 | 无 |

### 本系统的限价单触发逻辑（简化撮合）

```typescript
// lib/orderService.ts（引擎每 500ms 轮询）

// 限价买单：当前价 ≤ 挂单价格时触发
if (order.side === 'buy' && currentPrice <= order.price) {
  await fillOrder(order, order.price);
}

// 限价卖单：当前价 ≥ 挂单价格时触发
if (order.side === 'sell' && currentPrice >= order.price) {
  await fillOrder(order, order.price);
}
```

这等价于假设"市场上永远有对手方愿意以你指定的价格成交"，省略了真实撮合的复杂度。

## 总结

```
订单簿撮合 = 交易所用来配对买卖双方的核心机制

结构：
  ├── 买盘（Bid）：买方挂单，价格从高到低
  └── 卖盘（Ask）：卖方挂单，价格从低到高

撮合条件：买价 ≥ 卖价

优先级：价格优先 → 时间优先（FIFO）

市价单：立即从最优价开始逐档成交（产生滑点）
限价单：挂入订单簿等待，或立即以更优价成交

本系统：简化模型，无真实订单簿，轮询价格触发成交
```
