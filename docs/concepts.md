## 1. 现货交易是什么

**现货交易**（Spot Trading）是最基础的交易方式：用一种资产直接换另一种资产，价格即时（或接近即时）结算。

### 与合约交易的区别

| 维度 | 现货 | 合约（期货） |
|------|------|-------------|
| 持有物 | 真实的 BTC | 合约权益（不持有 BTC） |
| 杠杆 | 无（1倍） | 最高 125 倍 |
| 爆仓风险 | 最多亏光买入本金 | 可亏超本金 |
| [做空](./做空.md) | 需先持有 BTC | 可直接做空 |
| 适合人群 | 稳健投资者 | 高风险投机者 |

**本系统实现的是现货交易**：用 USDT 买 BTC，或用 BTC 换 USDT，无杠杆。

## 2. 账户与余额

本系统账户持有两种资产：**USDT**（法币稳定币）和 **BTC**（比特币）。

### 可用余额 vs 冻结余额

```
总余额 = 可用余额 + 冻结余额
```

- **可用余额**（available_balance）：可以用来下新订单的资金
- **冻结余额**（frozen_balance）：已被挂单占用、等待成交的资金

**举例**：
- 你有 10000 USDT
- 下了一个限价买单：用 1000 USDT 买 BTC（未成交）
- 此时：可用余额 = 9000 USDT，冻结余额 = 1000 USDT
- 撤单后：可用余额恢复到 10000 USDT，冻结余额 = 0

> 📌 系统实现：`accounts` 表中 `available_balance` + `frozen_balance`

## 3. 订单类型

### 3.1 市价单（Market Order）

**含义**：以当前市场最优价格立即成交。

- 优点：一定能成交，速度快
- 缺点：成交价不可控，高波动时可能比预期差[（滑点）](./滑点.md)
- 适用：急于买入/卖出，不在意几十美元的价格差异

**示例**：BTC 当前价 65000 USDT，下市价买单 0.01 BTC → 立即用 650 USDT 买入 0.01 BTC。

> 📌 系统实现：`type = 'market'`，下单时读取 `priceStore` 当前价，立即调用 `fillOrder` 成交。

### 3.2 限价单（Limit Order）

**含义**：指定一个价格，只有市场价到达该价格时才成交。

- 优点：成交价格可控
- 缺点：可能长时间挂单未成交，甚至永不成交
- 适用：想在特定价位买入/卖出

**示例**：
- 当前价 65000，你认为 63000 更值得买 → 下限价买单 @ 63000
- 价格跌到 63000 时自动成交
- 如果价格一直没跌到 63000，订单一直挂着

> 📌 系统实现：`type = 'limit'`，写入数据库状态为 `pending`，订单引擎每 500ms 检查触发条件。

## 4. 买入与卖出

现货交易只有两个方向：

| 方向 | 英文 | 含义 | 资产变化 |
|------|------|------|---------|
| 买入 | Buy  | 用 USDT 换 BTC | USDT ↓，BTC ↑ |
| 卖出 | Sell | 用 BTC 换 USDT | BTC ↓，USDT ↑ |

**现货只能先买后卖**（不能没有 BTC 就卖，这点和合约不同）。

> 📌 系统实现：`side = 'buy' | 'sell'`，下单前检查对应资产的 `available_balance` 是否充足。

## 5. 持仓

**持仓**（Position）表示你当前持有多少 BTC。

- 持仓量 = 历次买入数量之和 - 历次卖出数量之和
- 持仓量为 0 = 空仓（全仓换成 USDT）

**本系统是单向持仓**（只做多，即只持有 BTC 或空仓），不支持做空。

> 📌 系统实现：`positions` 表，`quantity` 字段表示当前持有 BTC 数量。

## 6. 均价与浮动盈亏

### 均价（Entry Price / Average Cost）

当你多次分批买入时，持仓的平均成本价格。

**计算公式**（加权平均）：
```
新均价 = (旧持仓量 × 旧均价 + 新买入量 × 新价格) / (旧持仓量 + 新买入量)
```

**举例**：
1. 第一次：买入 0.01 BTC @ 60000 → 均价 = 60000
2. 第二次：再买入 0.01 BTC @ 64000 → 均价 = (0.01×60000 + 0.01×64000) / 0.02 = **62000**

### 浮动盈亏（Unrealized PnL）

当前持仓在当前价格下的盈亏（还未卖出，只是"纸面盈亏"）。

```
浮动盈亏 = (当前价 - 均价) × 持仓量
```

**举例**：均价 62000，持仓 0.02 BTC，当前价 65000
```
浮动盈亏 = (65000 - 62000) × 0.02 = +60 USDT（浮盈 60 U）
```

> 📌 系统实现：`positions.entry_price`（均价）、`positions.unrealized_pnl`（浮动盈亏）。每次成交后重新计算并更新。

## 7. 止损（Stop Loss）

**止损**是一种风控机制：当价格跌到你设定的触发价时，自动卖出 BTC，避免亏损继续扩大。

### 工作原理

```
设置止损：触发价 = 62000（当前价 65000）

价格走势：65000 → 64000 → 63000 → 62000 ← 触发！
                                              ↓
                                        自动市价卖出 BTC
```

### 止损类型

| 类型 | 说明 |
|------|------|
| 市价止损 | 触发后以市价卖出，一定能成交，但价格不固定 |
| 限价止损 | 触发后以指定限价挂单，价格可控，但可能无法成交（继续下跌则错过） |

> 📌 系统实现：止损触发条件：`当前价 ≤ stop_price`。
> 市价单的止损通过创建子平仓挂单实现（`is_close_order = true`），限价单的止损字段直接存在订单上。

---

## 8. 止盈（Take Profit）

**止盈**是自动锁定利润的机制：当价格涨到你设定的目标价时，自动卖出 BTC，落袋为安。

### 工作原理

```
设置止盈：触发价 = 68000（当前价 65000）

价格走势：65000 → 66000 → 67000 → 68000 ← 触发！
                                              ↓
                                        自动市价卖出 BTC
```

### 止盈类型

| 类型 | 说明 |
|------|------|
| 市价止盈 | 触发后以市价卖出，成交快 |
| 限价止盈 | 触发后挂限价单，可能以更优价成交 |

> 📌 系统实现：止盈触发条件：`当前价 ≥ take_profit_price`。
> 和止损类似，通过子平仓挂单或直接存在订单字段上实现。

### 止损 vs 止盈对比

```
         止损区          当前价          止盈区
    ─────────┼──────────────┼──────────────┼─────
         62000          65000          68000
    价格向下穿越止损 → 卖出    价格向上穿越止盈 → 卖出
```

## 9. 订单生命周期

```
下单
  │
  ▼
pending（挂单中）
  │
  ├── 价格达到条件 / 市价立即 ──→ filled（已成交）
  │                                    │
  └── 用户手动撤单 ──────────────→ cancelled（已撤销）
                                       │
                              冻结资金解冻，退回可用余额
```

### 各状态说明

| 状态 | 含义 | 对应操作 |
|------|------|---------|
| `pending` | 挂单中，等待成交 | 可撤单 |
| `filled` | 已全部成交 | 无法操作 |
| `cancelled` | 已撤销 | 无法操作 |

> 📌 系统实现：`orders.status` 字段，引擎每 500ms 扫描所有 `pending` 订单。

## 10. 成交记录

每笔订单成交时，系统会记录一条成交明细：

| 字段 | 含义 |
|------|------|
| `price` | 实际成交价格 |
| `quantity` | 成交数量（BTC） |
| `fee` | 手续费（本系统设为 0） |
| `traded_at` | 成交时间 |

**注意**：一个订单可能分多次成交（部分成交），每次产生一条记录。本系统为简化实现，采用全量一次成交。

> 📌 系统实现：`trades` 表，每次成交调用 `fillOrder` 时写入。

## 11. K 线图

K 线（Candlestick Chart）是最常用的价格可视化方式，每根蜡烛代表一个时间周期内的价格变化。

### 一根 K 线包含 4 个数据

```
     │  ← 上影线（最高价）
   ┌─┴─┐
   │   │ ← 实体（开盘价到收盘价）
   │   │   绿色（阳线）= 收盘 > 开盘（上涨）
   └─┬─┘   红色（阴线）= 收盘 < 开盘（下跌）
     │  ← 下影线（最低价）
```

| 数据 | 含义 |
|------|------|
| 开盘价（Open） | 该时间段开始时的第一笔价格 |
| 收盘价（Close） | 该时间段结束时的最后一笔价格 |
| 最高价（High） | 该时间段内最高成交价 |
| 最低价（Low） | 该时间段内最低成交价 |

### 常见时间周期

| 代码 | 含义 | 适用场景 |
|------|------|---------|
| 1m | 1 分钟 | 超短线、盯盘 |
| 5m | 5 分钟 | 短线日内交易 |
| 15m | 15 分钟 | 短线趋势判断 |
| 1h | 1 小时 | 中线参考 |
| 4h | 4 小时 | 中长线趋势 |
| 1d | 日线 | 长线投资 |

> 📌 系统实现：前端通过 OKX WebSocket 订阅 `btcusdt@kline_Xm` 获取实时 K 线数据，由 TradingView 渲染。

## 12. 概念速查表

| 概念 | 英文 | 一句话解释 | 系统对应 |
|------|------|-----------|---------|
| 现货 | Spot | 直接买卖真实资产 | 整个系统 |
| 市价单 | Market Order | 以当前价立即成交 | `type='market'` |
| 限价单 | Limit Order | 到达指定价格才成交 | `type='limit'` |
| 买入 | Buy | 用 USDT 换 BTC | `side='buy'` |
| 卖出 | Sell | 用 BTC 换 USDT | `side='sell'` |
| 持仓 | Position | 当前持有 BTC 数量 | `positions.quantity` |
| 均价 | Entry Price | 持仓的平均买入成本 | `positions.entry_price` |
| 浮动盈亏 | Unrealized PnL | 未卖出时的纸面盈亏 | `positions.unrealized_pnl` |
| 止损 | Stop Loss | 价格下跌时自动卖出防止扩损 | `stop_price` |
| 止盈 | Take Profit | 价格上涨时自动卖出锁定利润 | `take_profit_price` |
| 可用余额 | Available Balance | 可以用来下单的资金 | `available_balance` |
| 冻结余额 | Frozen Balance | 被挂单占用的资金 | `frozen_balance` |
| 挂单 | Open Order | 尚未成交的订单 | `status='pending'` |
| 成交 | Fill / Trade | 订单实际买卖成功 | `status='filled'` |
| 撤单 | Cancel | 取消未成交挂单 | `status='cancelled'` |
| K 线 | Candlestick | 价格走势可视化图表 | TradingView Widget |
| 实时价 | Live Price | 当前最新成交价格 | `priceStore.getPrice()` |
