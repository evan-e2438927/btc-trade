# 产品需求文档：币安现货交易 BTC 模拟操盘 Demo（MVP）

## 1. 项目概述
### 1.1 项目背景
开发一个基于币安现货市场的 BTC 模拟交易演示页面，旨在为用户提供接近真实的交易操盘体验。通过该 MVP 版本，用户可以熟悉交易界面、K 线分析、买卖操作以及止盈止损设置，所有交易行为均为模拟操作，不涉及真实资产。

### 1.2 项目目标
- 构建一个轻量级的模拟交易前端页面，集成 TradingView 图表，展示 BTC/USDT 实时行情。
- 实现模拟买入、卖出、限价单、市价单及止盈止损订单功能。
- 后端提供订单模拟引擎，基于币安实时数据计算用户持仓和盈亏。
- 使用 PostgreSQL 存储用户账户、订单、持仓等数据。
- 为后续功能迭代打下基础。

## 2. 用户角色
- **模拟交易用户**：使用本 demo 进行 BTC 模拟操盘的用户。每个用户拥有虚拟资金（例如 10,000 USDT），可进行买卖操作。
- **系统管理员**（可选）：维护系统，查看数据库状态等。

## 3. 功能需求
### 3.1 核心交易功能
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 行情展示 | 集成 TradingView 图表，展示 BTC/USDT 的 K 线数据（来自币安数据源），支持时间周期切换（1m, 5m, 15m, 1h, 4h, 1d 等）。 | P0 |
| 当前价格 | 在交易面板显示 BTC 最新成交价、24h 涨跌幅、成交量等市场摘要信息。 | P0 |
| 买入/卖出操作 | 用户可选择“买入”或“卖出”，输入价格（限价单）或选择市价，输入数量，下单。系统根据当前币安实时价格进行模拟成交。 | P0 |
| 止盈止损 | 在下单时可设置止盈止损价格（止损价、止盈价），系统在价格触发时自动平仓（模拟）。 | P0 |
| 订单簿 | 显示当前市场的买一/卖一价和量（从币安获取）。 | P1 |
| 持仓管理 | 显示当前持仓（多头或空头）、持仓均价、浮动盈亏。 | P0 |
| 历史订单 | 查看已成交和未成交的订单记录。 | P1 |
| 账户信息 | 显示模拟账户的总资产（可用 USDT + 冻结 USDT + BTC 市值），以及总盈亏。 | P0 |

### 3.2 模拟订单执行逻辑
- **市价单**：立即以当前币安最新价成交（模拟撮合，不考虑滑点）。
- **限价单**：当币安最新价达到或优于限价时，模拟成交（可以简化：一旦最新价触及限价即按限价成交）。
- **止盈止损单**：属于条件单，当最新价触及止盈价或止损价时，自动以市价平仓（模拟）。
- **订单状态**：包括已提交、已成交、已取消、部分成交（暂不考虑部分成交，简化处理）。
- **成交记录**：每笔成交记录价格、数量、时间、手续费（可设为零）。

### 3.3 数据同步
- 前端通过 WebSocket 连接币安公共频道（或通过后端转发），获取实时 ticker 和 K 线数据。
- TradingView 图表数据可从前端直接通过币安 API 获取（或通过后端代理），以确保数据准确。

## 4. 非功能需求
- **响应时间**：下单操作响应时间 < 2 秒。
- **并发支持**：支持至少 100 个模拟用户同时在线操作。
- **数据准确性**：价格数据与币安保持同步，延迟不超过 2 秒。
- **安全性**：简单的身份认证（如 JWT），防止恶意操作；数据库加密存储敏感信息（如密码哈希）。
- **可扩展性**：代码结构清晰，便于后续添加新功能（如多种交易对、杠杆等）。

## 5. 技术架构与约束
- **前端**：Next.js（React 框架），使用 TypeScript。
  - TradingView 库：使用 TradingView 轻量级图表或高级图表（需申请库）。
  - WebSocket 客户端：连接币安 WebSocket 或后端代理。
- **后端**：Node.js（Express 或 NestJS），提供 RESTful API 和 WebSocket 服务。
  - 模拟订单引擎：维护用户订单状态，监听价格触发条件。
  - 与币安数据源对接：通过 WebSocket 获取实时行情，用于触发条件单和更新用户持仓盈亏。
- **数据库**：PostgreSQL，运行在 Docker 容器中（已在另一台机器部署）。
  - 表结构设计：用户表、账户表、订单表、持仓表、交易记录表等。
- **部署**：前后端可分别部署，使用环境变量配置数据库连接和币安 API 端点。

## 6. 数据库设计（简略）
### 6.1 用户表 (users)
- id (PK)
- username (唯一)
- password_hash
- email
- created_at
- updated_at

### 6.2 账户表 (accounts)
- id (PK)
- user_id (FK)
- asset (例如 'USDT', 'BTC')
- available_balance (可用余额)
- frozen_balance (冻结余额，用于挂单)
- updated_at

### 6.3 订单表 (orders)
- id (PK)
- user_id (FK)
- symbol (如 'BTCUSDT')
- side (buy/sell)
- type (market/limit/stop_limit/stop_market 等)
- price (限价)
- stop_price (止损触发价，可选)
- take_profit_price (止盈价，可选)
- quantity (数量)
- executed_quantity (已成交数量)
- status (pending, filled, cancelled, triggered)
- created_at
- updated_at

### 6.4 持仓表 (positions)
- id (PK)
- user_id (FK)
- symbol
- quantity (正数为多头，负数为空头)
- entry_price (平均开仓价)
- unrealized_pnl
- updated_at

### 6.5 成交记录表 (trades)
- id (PK)
- order_id (FK)
- price
- quantity
- fee
- fee_asset
- traded_at

## 7. 界面原型描述
### 7.1 主布局
- 顶部导航栏：显示模拟账户总资产、可用 USDT、BTC 持仓、总盈亏。
- 左侧/中央：TradingView 图表区域，覆盖大部分空间。
- 右侧：交易面板，包括：
  - 当前价格卡片（最新价、涨跌幅）
  - 买入/卖出切换按钮
  - 订单类型选择（限价/市价）
  - 价格输入框（限价单时显示）
  - 数量输入框
  - 止盈止损设置区域（可展开）
  - 下单按钮
- 下方：订单簿（买盘/卖盘）、持仓列表、订单历史（通过标签页切换）。

### 7.2 交互细节
- 点击买入/卖出后，下单按钮文字相应变化。
- 下单成功后弹出提示，持仓和账户余额实时更新。
- 止盈止损设置：提供复选框和价格输入框，用户可以同时设置止损和止盈。
- K线图支持十字光标、技术指标等基础功能。

## 8. 开发阶段与优先级
### 第一阶段（MVP 核心功能）
- 搭建 Next.js 前端框架，集成 TradingView 图表（使用币安数据）。
- 后端实现用户注册/登录（简单 JWT 认证）。
- 实现市价单和限价单的下单、成交逻辑。
- 数据库设计及基础 CRUD。
- 账户余额初始化（每个新用户 10,000 USDT）。
- 实时价格展示和持仓盈亏计算。

### 第二阶段（增强功能）
- 止盈止损条件单的监听与触发。
- 订单历史记录和详情。
- 简单的订单簿展示。
- 部署测试。

### 第三阶段（优化）
- 性能优化、错误处理。
- 前端体验改进（如输入校验、键盘快捷键）。
- 可能添加简单的模拟回测功能（可选）。

## 9. 验收标准
- 用户可以注册并登录系统。
- 登录后可以看到 BTC/USDT 实时 K 线图。
- 用户可以以市价或限价买入/卖出 BTC，账户余额和持仓随之更新。
- 用户可以设置止盈止损，并在价格触发时自动平仓。
- 订单记录准确显示。
- 页面响应流畅，无明显卡顿。
- 数据库数据与前端展示一致。

## 10. 风险与假设
- **风险**：币安 API 变更或限制访问，需准备备选方案或使用第三方聚合 API。
- **风险**：WebSocket 连接稳定性，需实现自动重连机制。
- **假设**：模拟撮合逻辑简化处理，忽略深度和滑点，仅根据最新价判断成交。
- **假设**：用户数量不多，暂不考虑分布式订单引擎。
